# Before a public research-paper claim

Software release completion and scientific validation are separate decisions.
This list preserves outstanding work rather than calling configurations results.

- Select a license for original IAP code; verify graph/checkpoint redistribution.
- Set the real repository URL in citation/metadata after creating the repository;
  do not invent a DOI, publication venue, acceptance, or paper identifier.
- Complete a primary-source related-work review. Separate ordinary distillation,
  active learning, structural matching, transfer across MDP abstractions and
  policy/option translation from any genuinely new combination or result.
- Freeze endpoints, seeds and budgets before new confirmation. Add independent
  teacher seeds and task families, not only new sensor/ontology instances.
- Run the supplied fresh fixed-teacher configuration separately from historical
  regression; stronger teacher/task generalization needs additional designs.
- Add aligned distillation, compact truth table, direct query learning with its
  own active strategy, and structure-aware no-packet baselines. These are not
  claimed completed here.
- Count structure-discovery cost, labelled calibration information, teacher
  compute, decoder code/priors, all packet framing, exposure draws, unique states,
  replay batches, receiver compute and energy where relevant.
- Use paired world/seed units and account for fixed teachers/shared connectome
  structure. Avoid episode/state pseudoreplication and post-hoc endpoint selection.
- Retain failures, seed sensitivity, all initializations and the Doom negatives.
- Re-run on an independent machine; record Windows CI results when available.
- Publish immutable raw outputs, source/config/asset hashes, limitations and an
  accurate artifact-availability statement with the manuscript.
